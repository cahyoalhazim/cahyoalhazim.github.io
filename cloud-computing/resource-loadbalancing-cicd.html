Resource Pooling, Sharing and Provisioning

1. Resource Pooling ▼

Definisi: Menggabungkan dan mengelola sumber daya komputasi (storage, CPU, memory, networking) agar dapat dibagikan ke banyak pengguna/aplikasi.


Karakteristik:

  • Abstraksi Lokasi - Pengguna tidak tahu lokasi fisik resource
  • Alokasi Dinamis - Resource dialokasikan sesuai demand
  • Efisiensi - Mengurangi idle resource

3. Resource Sharing and Multi-Tenancy ▼

Multi-Tenancy: Satu resource element mendukung multiple consumers (tenants) dengan isolasi antar tenant.


Levels of Multi-Tenancy:

  • IaaS - Shared computing infrastructure (servers, storage)
  • PaaS - Shared OS, multiple apps from different vendors
  • SaaS - Single app instance serves multiple consumers

4. Resource Provisioning ▼

Definisi: Proses menyediakan dan mengalokasikan computing resources untuk memenuhi kebutuhan user/aplikasi.


ApproachDescriptionProsCons
StaticFixed allocation, tidak berubah selama VM berjalanSimple, no runtime overheadTidak handle demand spikes, inefficient
DynamicFlexible adjustment on-demand selama runtimeAdaptif, pay-per-usage, scalableRuntime overhead, minor delays
HybridStatic awal + dynamic selanjutnyaBalance efficiency and flexibilityLebih kompleks

Provisioning Plans:

  • Short-term On-Demand: Pay-per-usage, dynamic, untuk demand unpredictable
  • Long-term Reservation: Fixed fee untuk periode tertentu, untuk demand predictable
5. SLA (Service Level Agreement) ▼

SLA adalah kontrak antara consumer dan provider yang menentukan:

  • Expected computing resource capacity
  • Availability guarantees (e.g., 99.9% uptime)
  • Performance metrics
  • Penalties untuk breach

Provider menggunakan SLA untuk estimate resource needs dan melakukan resource mapping.

2. Elastic Computing ▼

Elastic Computing adalah kemampuan untuk secara dinamis menambah/mengurangi server sesuai peak times.


Karakteristik:

  • Rapid creation/removal - Fully software-managed
  • Physical sharing - Multiple VMs on single physical server
  • Logical isolation - VMs terisolasi meski di server fisik yang sama

Project: github.com/jrgarciadev/nextjs-todo-list

3 Buat Deploy Token (GitHub Personal Access Token)

GitHub Personal Access Token (PAT):

  1. Buka GitHub -> Settings -> Developer settings -> Personal access tokens -> Tokens (classic)
  2. Klik "Generate new token (classic)"
  3. Beri nama: nextjs-deploy-token
  4. Select scopes:
    • repo (full control of private repositories)
    • workflow (update GitHub Action workflows)
    • write:packages (upload packages to GitHub Package Registry)
  5. Klik "Generate token"
  6. COPY TOKEN SEKARANG (tidak bisa dilihat lagi!)

Simpan sebagai GitHub Secret:

  1. Buka repository GitHub -> Settings -> Secrets and variables -> Actions
  2. Klik "New repository secret"
  3. Name: DEPLOY_TOKEN
  4. Value: Paste token yang tadi dibuat
  5. Klik "Add secret"
# Alternatif: Gunakan GitHub CLI
gh auth login
gh secret set DEPLOY_TOKEN --body "ghp_xxxxxxxxxxxx"

5 Buat GitHub Actions Workflow

Buat file .github/workflows/ci-cd.yml:

name: CI/CD Pipeline - Next.js Todo App

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

env:
  NODE_VERSION: '20'
  VERCEL_ORG_ID: ${{ secrets.VERCEL_ORG_ID }}
  VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}

jobs:
  # --- Stage 1: Lint & Type Check ---
  lint:
    name: Lint & Type Check
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run ESLint
        run: npm run lint

      - name: Type check with TypeScript
        run: npx tsc --noEmit

  # --- Stage 2: Unit Tests ---
  test:
    name: Unit Tests
    runs-on: ubuntu-latest
    needs: lint
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests with coverage
        run: npm run test

      - name: Upload coverage report
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: coverage-report
          path: coverage/
          retention-days: 7

  # --- Stage 3: Build ---
  build:
    name: Build Application
    runs-on: ubuntu-latest
    needs: [lint, test]
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Build Next.js app
        run: npm run build

      - name: Upload build artifacts
        uses: actions/upload-artifact@v4
        with:
          name: build-output
          path: .next/
          retention-days: 1

  # --- Stage 4: Deploy to Vercel (Production) ---
  deploy-production:
    name: Deploy to Production
    runs-on: ubuntu-latest
    needs: [lint, test, build]
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    environment:
      name: production
      url: ${{ steps.deploy.outputs.url }}
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Install Vercel CLI
        run: npm install --global vercel@latest

      - name: Pull Vercel Environment Information
        run: vercel pull --yes --environment=production --token=${{ secrets.VERCEL_TOKEN }}

      - name: Build Project Artifacts
        run: vercel build --prod --token=${{ secrets.VERCEL_TOKEN }}

      - name: Deploy Project Artifacts to Vercel
        id: deploy
        run: |
          url=$(vercel deploy --prebuilt --prod --token=${{ secrets.VERCEL_TOKEN }})
          echo "url=$url" >> $GITHUB_OUTPUT
          echo "Deployed to: $url"

      - name: Comment Deployment URL
        if: success()
        uses: actions/github-script@v7
        with:
          script: |
            const { data: comment } = await github.rest.repos.createCommitComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              commit_sha: context.sha,
              body: `**Production Deployed Successfully!**\n\nURL: ${{ steps.deploy.outputs.url }}`
            })

  # --- Stage 5: Deploy Preview (Pull Requests) ---
  deploy-preview:
    name: Deploy Preview
    runs-on: ubuntu-latest
    needs: [lint, test, build]
    if: github.event_name == 'pull_request'
    environment:
      name: preview
      url: ${{ steps.deploy-preview.outputs.url }}
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Install Vercel CLI
        run: npm install --global vercel@latest

      - name: Pull Vercel Environment Information
        run: vercel pull --yes --environment=preview --token=${{ secrets.VERCEL_TOKEN }}

      - name: Build Project Artifacts
        run: vercel build --token=${{ secrets.VERCEL_TOKEN }}

      - name: Deploy Preview
        id: deploy-preview
        run: |
          url=$(vercel deploy --prebuilt --token=${{ secrets.VERCEL_TOKEN }})
          echo "url=$url" >> $GITHUB_OUTPUT

      - name: Comment Preview URL on PR
        uses: actions/github-script@v7
        with:
          script: |
            await github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `**Preview deployed:** ${{ steps.deploy-preview.outputs.url }}`
            })

8 Verifikasi Pipeline

Checklist Verifikasi:

  • Repository di-fork ke akun pribadi
  • GitHub Secrets (VERCEL_TOKEN, VERCEL_ORG_ID, VERCEL_PROJECT_ID) sudah di-set
  • File .github/workflows/ci-cd.yml sudah dibuat
  • Push ke branch main berhasil
  • Tab Actions menunjukkan workflow berjalan
  • Job "Lint & Type Check" pass (hijau)
  • Job "Unit Tests" pass dengan coverage report
  • Job "Build Application" pass
  • Job "Deploy to Production" berhasil deploy ke Vercel
  • URL deployment bisa diakses di browser

Troubleshooting:

# Jika build gagal, cek logs:
# 1. Buka GitHub -> repository -> Actions -> failed workflow
# 2. Klik job yang failed untuk melihat detail error
# 3. Common issues:
#    - Missing secrets: pastikan VERCEL_TOKEN dll sudah di-set
#    - Node version mismatch: pastikan package.json compatible
#    - Missing test script: tambahkan "test": "jest" di package.json

# Test locally sebelum push:
npm ci
npm run lint
npm run test
npm run build
9 GitLab CI/CD Alternative (Opsional)

Jika menggunakan GitLab, buat file .gitlab-ci.yml:

stages:
  - build
  - test
  - deploy

variables:
  NODE_VERSION: "20"
  VERCEL_TOKEN: $VERCEL_TOKEN
  VERCEL_ORG_ID: $VERCEL_ORG_ID
  VERCEL_PROJECT_ID: $VERCEL_PROJECT_ID

# Cache node_modules
cache:
  paths:
    - node_modules/

build:
  stage: build
  image: node:20-alpine
  script:
    - npm ci
    - npm run build
  artifacts:
    paths:
      - .next/
    expire_in: 1 hour

test:
  stage: test
  image: node:20-alpine
  script:
    - npm ci
    - npm run lint
    - npm run test
  coverage: '/All files[^|]*\|[^|]*\s+([\d\.]+)/'

deploy:
  stage: deploy
  image: node:20-alpine
  script:
    - npm install -g vercel
    - vercel pull --yes --environment=production --token=$VERCEL_TOKEN
    - vercel build --prod --token=$VERCEL_TOKEN
    - vercel deploy --prebuilt --prod --token=$VERCEL_TOKEN
  only:
    - main

Setup GitLab CI/CD Variables:

  1. Buka GitLab -> Project -> Settings -> CI/CD -> Variables
  2. Add variables: VERCEL_TOKEN, VERCEL_ORG_ID, VERCEL_PROJECT_ID
  3. Protect variables jika hanya untuk protected branches
  4. Mask variables untuk keamanan
