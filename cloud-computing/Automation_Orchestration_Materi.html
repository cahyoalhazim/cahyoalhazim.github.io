📚 Pengantar Automation & Orchestration

Automation fokus pada membuat tugas lebih mudah dan cepat untuk dilakukan manusia.
Orchestration adalah automation dengan scope yang lebih besar - mengkoordinasikan banyak tugas otomatis menjadi satu sistem yang utuh.

3 Kategori User Cloud Automation

👤 Individual Customers

Pengguna individu yang menggunakan SaaS apps (Google Docs, Office 365). Provider menyediakan akses via web browser atau dedicated app dengan interface yang menyederhanakan detail teknis.

🏢 Large Cloud Customers

Enterprise/organisasi yang membutuhkan tools untuk mengontrol dan mengelola computing resources di public cloud. Memerlukan automated tools untuk deploy dan manage infrastruktur.

🏗️ Cloud Providers

Provider cloud membuat tools paling sophisticated untuk mengelola cloud data center, termasuk tools untuk configure, monitor, dan manage underlying infrastructure serta handle requests dari customers.

⚙️ Automation dalam Data Center

4 Aspek Data Center yang Kompleks

Aspek Deskripsi
Extreme Scale Ribuan rack, perangkat, dan koneksi yang harus dikelola
Diverse Services Berbagai macam layanan dengan kebutuhan berbeda-beda
Constant Change Perubahan konfigurasi dan deployment yang terus-menerus
Human Error Kesalahan manusia yang perlu diminimalisir dengan otomatisasi

Apa Saja yang Bisa Di-Automate?

🖥️ Creation & Deployment

VMs, containers, virtual storage (SAN/NAS), virtual networks (VLANs, subnets, IP forwarding)

📊 Workload Monitoring

Measurement load servers, tracking resource use per tenant, identifikasi hot spots, capacity assessment

⚡ Optimizations

Load balancing, latency minimization, VM migration, power usage optimization

🛡️ Safety & Recovery

Scheduled backups, server monitoring, fast rerouting, RAID monitoring, automated restart

🔄 Software Updates

OS updates, software upgrades, continuous deployment facilities

🔒 Security Policies

Firewall deployment, tenant data protection, secrets management, encryption

Level of Automation

Level 1: Manual → Level 2: Assisted → Level 3: Partial Automation → Level 4: Conditional Automation → Level 5: Full Automation

Semakin tinggi level, semakin sedikit intervensi manusia yang dibutuhkan.

🎼 Dari Automation ke Orchestration

Feature Automation Orchestration
Tasks Single, repetitive Sequence of tasks
Decision Making Minimal Complex
Scale Task-level System/multi-environment
Tools Scripts (Bash, Ansible) Orchestrators (Kubernetes)
Human Oversight Initial config Initial setup
Analogi: Automation = building blocks (batu bata). Orchestration = the conductor (konduktor) yang menyelaraskan semua automation menjadi harmoni sistem yang utuh.

Mengapa Orchestration Diperlukan?

🚀 Rapid Creation

Manual automation tidak scalable. Aplikasi modern terdiri dari ratusan/rbuan container dan microservices.

⏱️ Short Lifetime

Container sering start, stop, atau migrate antar nodes. Orchestration menangani dependency, recovery, dan state consistency.

📈 Replication

Essential untuk large-scale cloud environments. Memastikan startup order yang benar dan service dependencies (DB sebelum API).

Key Insight: Automation = local (fokus pada satu aspek). Orchestration = global (mengkoordinasikan semua subsystem untuk mengoperasikan service).

☸️ Kubernetes (K8s) Overview

Kubernetes adalah open-source orchestration system untuk containers, originally developed by Google, sekarang maintained by Cloud Native Computing Foundation (CNCF).

Apa yang Dikelola Kubernetes?

  • ✅ Replication dan load balancing
  • ✅ Fault recovery dan self-healing
  • ✅ Scaling (horizontal auto-scaling)
  • ✅ Deployment rollouts dan rollbacks
  • ✅ Service discovery dan load balancing
  • ✅ Storage orchestration
  • ✅ Secret dan configuration management

Limitations Kubernetes

Kubernetes TIDAK: mengelola source code, build containers, supply event-passing middleware, handle monitoring/event logging, atau focus pada specific application type. Untuk hal tersebut diperlukan tools terpisah.

Control Plane Components

Component Fungsi
API Server Central switchboard, semua komunikasi internal/external melalui API server
etcd Cluster state store, distributed key-value store untuk menyimpan config dan state
Scheduler Menentukan worker node mana yang akan menjalankan pod baru
Controller Manager Menjalankan controller processes (node controller, replication controller, dll)
Cloud Controller Manager Integrasi dengan cloud provider (AWS, GCP, Azure)

Worker Node Components

Component Fungsi
Kubelet Agent yang berkomunikasi dengan Master Node, menerima instruksi dan mengirim status pod
Service Proxy Mengkonfigurasi iptables untuk intra-node dan inter-node communication
cAdvisor Embedded dalam Kubelet, mengumpulkan container-level metrics
Container Runtime Menjalankan container operations (dockerd, containerd)

Pods: Unit Terkecil

Pod adalah unit deployable terkecil di Kubernetes. Bisa berisi satu atau lebih container yang tightly coupled, sharing storage, network, dan configuration. Setiap pod mendapat IP address unik.

Init Containers

Init containers berjalan SEBELUM main containers start. Digunakan untuk:

  • Verifikasi external storage tersedia
  • Check repositories/services yang diperlukan
  • Setup permissions atau konfigurasi awal

Jika init container gagal, main containers TIDAK akan dijalankan.

Kubernetes Key Features

Feature Deskripsi Benefit
Replicas Kontrol jumlah pod copies Scalability & load management
Deployments Automated scaling dengan intent-based model Maintains desired replicas
StatefulSets Manage stateful apps dengan persistent identity Predictable naming & data persistence
DaemonSets Run pod di setiap node Node-level services (logging/monitoring)
Jobs Run pods sampai completion Reliable task completion
CronJobs Schedule jobs periodically Automated recurring tasks
Services Stable access policy & load balancing Consistent access, decoupled clients

Benefits Orchestration

🛡️ Reliability

Self-healing, fault tolerance, reduced human error

Auto-scaling, load balancing, simplified large deployments

🚀 CI/CD

Foundation untuk cloud-native applications dan continuous deployment

🔧 Hands-On Lab 1: Ansible Web Server Deployment

Tujuan: Menggunakan Ansible untuk mengotomatisasi deployment Nginx web server di Ubuntu dengan konten dinamis yang menampilkan hostname dan IP address.

🎯 Prasyarat & Environment Setup

Role Hostname IP Address Purpose
Control Node cloud 192.168.56.105 Menjalankan Ansible
Managed Node cloudclone 192.168.56.106 Target server (Nginx)
Pastikan kedua VM dapat saling ping: ping 192.168.56.106 dari control node.

1 Install Ansible di Control Node

# Update package list
sudo apt update

# Install Ansible dan SSH client/server
sudo apt install -y ansible openssh-client openssh-server

# Verifikasi instalasi
ansible --version

2 Konfigurasi SSH Key-Based Authentication

# Generate SSH key pair (di control node)
ssh-keygen -t rsa -b 4096 -f ~/.ssh/id_rsa_ansible -N ""

# Copy public key ke managed node (192.168.56.106)
ssh-copy-id -i ~/.ssh/id_rsa_ansible.pub cloud@192.168.56.106

# Jika SSH belum aktif di target, install dulu:
sudo apt install -y openssh-server
sudo systemctl enable --now ssh

# Test SSH access tanpa password
ssh -i ~/.ssh/id_rsa_ansible cloud@192.168.56.106

3 Buat Struktur Project Ansible

mkdir -p ~/ansible-project
cd ~/ansible-project

# Struktur direktori yang akan dibuat:
~/ansible-project/
├── inventory
├── site.yml
└── index.html.j2

4 Buat Inventory File

# Buat file inventory
cat > inventory << 'EOF'
[webservers]
192.168.56.105 ansible_user=cloud ansible_ssh_private_key_file=~/.ssh/id_rsa_ansible
192.168.56.106 ansible_user=cloud ansible_ssh_private_key_file=~/.ssh/id_rsa_ansible
EOF

# Verifikasi inventory
ansible-inventory -i ./inventory --list

5 Test Konektivitas

# Ping test ke semua webservers
ansible -i ./inventory webservers -m ping

# Expected output:
192.168.56.106 | SUCCESS => {"changed": false, "ping": "pong"}

6 Buat Main Playbook (site.yml)

cat > site.yml << 'EOF'
---
- name: Deploy nginx and simple web page on webservers
  hosts: webservers
  become: yes
  gather_facts: yes

  tasks:
    - name: Update apt cache
      ansible.builtin.apt:
        update_cache: yes
        cache_valid_time: 3600

    - name: Ensure nginx is installed
      ansible.builtin.apt:
        name: nginx
        state: present

    - name: Ensure /var/www/html exists
      ansible.builtin.file:
        path: /var/www/html
        state: directory
        mode: '0755'
        owner: www-data
        group: www-data

    - name: Deploy index.html showing hostname and IPs
      ansible.builtin.template:
        src: index.html.j2
        dest: /var/www/html/index.html
        mode: '0644'
        owner: www-data
        group: www-data

    - name: Ensure nginx is started and enabled
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: yes
EOF
Penjelasan Playbook:
• become: yes → Jalankan dengan sudo privileges
• gather_facts: yes → Kumpulkan info sistem (hostname, IP, dll)
• ansible.builtin.apt → Module untuk package management
• ansible.builtin.template → Deploy file dari template Jinja2
• ansible.builtin.service → Manage systemd services

7 Buat HTML Template (Jinja2)

cat > index.html.j2 << 'EOF'
<html>
<head><title>Deployed by Ansible</title></head>
<body>
  <h1>Hello from {{ ansible_hostname }}!</h1>
  <p>IP addresses:</p>
  <ul>
    {%- if ansible_default_ipv4 is defined and ansible_default_ipv4.address is defined %}
    <li>{{ ansible_default_ipv4.address }}</li>
    {%- else %}
    {%- for iface in ansible_facts.interfaces | sort %}
    {%- set key = 'ansible_' + iface %}
    {%- if (key in ansible_facts) and (ansible_facts[key].ipv4 is defined) %}
    <li>{{ iface }}: {{ ansible_facts[key].ipv4.address }}</li>
    {%- endif %}
    {%- endfor %}
    {%- endif %}
  </ul>
  <p>Deployed on {{ ansible_date_time.date }} {{ ansible_date_time.time }}</p>
</body>
</html>
EOF
Variabel Jinja2 yang Digunakan:
• {{ ansible_hostname }} → Nama host target
• {{ ansible_default_ipv4.address }} → IP address default
• {{ ansible_facts.interfaces }} → List network interfaces
• {{ ansible_date_time.date }} → Tanggal deployment

8 Jalankan Playbook

# Jalankan playbook
ansible-playbook -i ./inventory site.yml

# Jika diminta sudo password, gunakan flag -K:
ansible-playbook -i ./inventory site.yml -K

# Output yang diharapkan:

TASK [Gathering Facts] ******************************************
ok: [192.168.56.106]
TASK [Update apt cache] *****************************************
changed: [192.168.56.106]
TASK [Ensure nginx is installed] ********************************

TASK [Ensure /var/www/html exists] ****************************

9 Verifikasi Deployment

# Cek status nginx
systemctl status nginx

# Test dari control node menggunakan curl
curl http://192.168.56.106

# Atau buka browser dan akses:
http://192.168.56.106
Expected Result: Browser akan menampilkan halaman dengan judul "Deployed by Ansible", heading "Hello from cloudclone!", list IP addresses, dan timestamp deployment.

📋 Checklist Lab Ansible

  • VM Control Node dan Managed Node saling terhubung
  • Ansible terinstall di Control Node
  • SSH key-based authentication berfungsi tanpa password
  • Inventory file terkonfigurasi dengan benar
  • Playbook berhasil dijalankan tanpa error
  • Nginx berjalan dan enabled di managed node
  • Halaman web menampilkan hostname dan IP dinamis
  • Template Jinja2 berhasil dirender dengan variabel Ansible facts

☸️ Hands-On Lab 2: Kubernetes Basics

Tujuan: Memahami konsep dasar Kubernetes dengan membuat Pod, Deployment, dan Service menggunakan minikube atau cluster lokal.

🎯 Prasyarat

  • minikube terinstall (curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64)
  • kubectl terinstall (sudo snap install kubectl --classic)
  • Docker atau container runtime tersedia

1 Start Minikube Cluster

# Start minikube dengan driver docker
minikube start --driver=docker

# Verifikasi status
minikube status

# Cek nodes
kubectl get nodes

2 Buat Pod Manifest

cat > pod-nginx.yml << 'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: web
    tier: frontend
spec:
  containers:
  - name: nginx
    image: nginx:latest
    ports:
    - containerPort: 80
EOF

3 Deploy Pod

# Apply manifest
kubectl apply -f pod-nginx.yml

# Lihat pod yang berjalan
kubectl get pods -o wide

# Detail pod
kubectl describe pod nginx-pod

# Logs pod
kubectl logs nginx-pod

4 Buat Deployment (Best Practice)

cat > deployment-nginx.yml << 'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
        resources:
          requests:
            memory: "64Mi"
            cpu: "100m"
          limits:
            memory: "128Mi"
            cpu: "200m"
EOF
Deployment vs Pod: Deployment mengelola ReplicaSet yang mengelola Pods. Jika Pod mati, Deployment akan otomatis membuat Pod baru untuk memenuhi replicas: 3.

5 Deploy dan Scale

# Apply deployment
kubectl apply -f deployment-nginx.yml

# Cek deployment dan pods
kubectl get deployment
kubectl get pods

# Scale ke 5 replicas
kubectl scale deployment nginx-deployment --replicas=5

# Cek lagi - sekarang ada 5 pods
kubectl get pods

6 Buat Service (Exposing Pods)

cat > service-nginx.yml << 'EOF'
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: NodePort
EOF
# Apply service
kubectl apply -f service-nginx.yml

# Cek service
kubectl get service nginx-service

# Akses service via minikube
minikube service nginx-service --url

# Atau buka browser otomatis
minikube service nginx-service

7 Self-Healing Demo

# Lihat pods yang berjalan
kubectl get pods

# Hapus salah satu pod (simulasi failure)
kubectl delete pod nginx-deployment-xxx-yyy

# Amati - Deployment akan otomatis membuat pod baru!
kubectl get pods -w

# Tekan Ctrl+C untuk berhenti watch
Self-Healing: Kubernetes mendeteksi bahwa jumlah pod berkurang dari 5 (desired state). Controller Manager otomatis membuat pod baru untuk mengembalikan state ke yang diinginkan.

8 Rolling Update

# Update image ke versi baru
kubectl set image deployment/nginx-deployment nginx=nginx:1.26

# Monitor rolling update
kubectl rollout status deployment/nginx-deployment

# Cek history
kubectl rollout history deployment/nginx-deployment

# Rollback jika ada masalah
kubectl rollout undo deployment/nginx-deployment

9 Cleanup

# Hapus semua resources
kubectl delete -f pod-nginx.yml
kubectl delete -f deployment-nginx.yml
kubectl delete -f service-nginx.yml

# Atau hapus semua sekaligus
kubectl delete all --all

# Stop minikube
minikube stop

📋 Checklist Lab Kubernetes

  • Minikube cluster berjalan tanpa error
  • Pod nginx berhasil dibuat dan running
  • Deployment dengan 3 replicas berjalan
  • Scaling dari 3 ke 5 replicas berhasil
  • Service NodePort berhasil expose pods
  • Self-healing bekerja saat pod dihapus
  • Rolling update ke image baru berhasil
  • Rollback ke versi sebelumnya berfungsi

🧠 Konsep Kunci yang Dipelajari

📦 Pod

Unit terkecil yang berisi satu atau lebih container yang share network dan storage.

📋 Deployment

Mengelola ReplicaSet untuk memastikan jumlah pod sesuai desired state.

🔌 Service

Abstraksi yang mendefinisikan logical set of pods dan policy untuk mengaksesnya.

🎯 Desired State

Kubernetes terus-menerus membandingkan actual state dengan desired state dan melakukan koreksi.

🎓 Ringkasan & Evaluasi

Perbedaan Automation vs Orchestration

Automation = Script yang menjalankan tugas individual (install nginx, copy file).

Orchestration = Sistem yang mengkoordinasikan banyak automation untuk mencapai system state yang diinginkan (deploy 3 replicas nginx, load balance, auto-heal, scale).

Kapan Menggunakan Ansible vs Kubernetes?

Skenario Tools Alasan
Provision VM, install software, konfigurasi OS Ansible Agentless, idempotent, simple
Manage container lifecycle, scaling, self-healing Kubernetes Container orchestration native
Deploy infrastructure di cloud (AWS, GCP, Azure) Terraform + Ansible Infrastructure as Code
CI/CD pipeline automation Jenkins/GitLab CI Build, test, deploy automation

Pertanyaan Diskusi

  2. Apa risiko jika kita hanya menggunakan script bash untuk manage 1000+ containers tanpa orchestrator?
  3. Bagaimana Kubernetes menangani situasi ketika sebuah worker node mati total?
  4. Jelaskan peran etcd dalam menjaga consistency cluster state!
